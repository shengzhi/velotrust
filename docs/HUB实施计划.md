# VeloTrust HUB 实施计划

本计划以[HUB 服务功能需求文档](HUB服务功能需求文档.md)为验收基线，复用现有 PostgreSQL 数据模型和 gRPC 控制流。首期目标是完成单实例 Gateway、Client 控制闭环；HA 不作为首期已完成能力。

## 实施原则

- 先建立可验证的身份边界，再处理任何心跳、配置、状态或撤销业务消息。
- Gateway 注册后的 gRPC 认证复用已绑定的 WireGuard X25519 公钥；一次性注册凭证只处理首次准入。
- Management 继续拥有节点审批、配置和策略的业务权威；HUB 通过 Repository/事务读取并写入运行态，不复制 Management 的业务规则。
- 首期单实例会话可由进程运行态管理；数据库中的当前节点、配置和任务状态仍是事实来源。任何进程内状态都不作为后续 HA 的唯一来源。
- 每阶段保留可构建的代码和明确的未完成边界，不把协议骨架描述成已完成业务。

## 阶段计划

| 阶段 | 范围 | 主要交付 | 验收重点 |
|---|---|---|---|
| 0. 控制协议与安全基线 | Gateway/Client X25519 新鲜挑战、TLS exporter 通道绑定、显式明文模式、协议消息及稳定错误码 | 扩展 `shared/proto/v1/hub.proto`、重新生成 Go 代码、增加可复用认证算法和协议说明 | 错误密钥、过期挑战、跨流重放、错误通道绑定均拒绝；业务消息只能出现在认证完成后 |
| 1. Gateway 会话 | 节点目录校验、会话生命周期、心跳、在线状态及优雅断开 | HUB Repository、Gateway 双向流处理、心跳/租约配置、运行日志 | 只接受 active 且公钥匹配的 Gateway；旧会话不能覆盖新会话；断开可清理 |
| 2. Gateway 首次注册 | 一次性注册凭证校验、X25519 持钥证明、凭证消费与公钥绑定事务、审批状态 | 控制流注册握手、PostgreSQL Repository 与现有迁移核对 | 只能成功一次；错误、撤销、过期、并发重放不会留下半提交状态；待审批 Gateway 不得取配置 |
| 3. 当前配置同步 | 当前配置读取、hash 对账、配置快照发送、任务状态更新与回执 | Config Source、任务/事件 Repository、控制流内在线派发 | 只下发节点当前授权配置；旧回执不能倒退状态；重连从数据库重新对账 |
| 4. 撤销、状态与运维 | 节点停用/隔离/撤销通知、真实执行回执、状态报告、诊断审计、健康依赖状态 | 状态/审计 Repository、消息通知和后台对账 | 离线撤销保持待处理；重连先检查生命周期；秘密不进入日志 |
| 5. Client 接入 | 员工账号密码登录、TLS 保护、首次设备登记、设备与 WireGuard 公钥绑定、配置同步、在线撤销 | Client 员工认证、X25519 设备证明、配置快照应用、运行状态/回执、禁用后的本机隧道清理 | 错误密码、伪造 node ID、禁用设备、停用员工或未绑定公钥均拒绝；Client 不访问 Management API |
| 6. 可组合部署 | Management 与 HUB 分别启动/共同进程运行，共享基础设施但独立生命周期 | Composition root、部署配置、健康探针与手册 | 两种部署复用同一 HUB 服务实现 |
| 7. HA 后续阶段 | 会话租约、跨实例派发、事件通知、幂等重试和故障恢复 | 新增迁移、共享协调接口和多实例可观测性 | 实例切换、通知丢失、重放、过期租约及故障恢复场景 |

## 当前实施切片

阶段 0–3 已有 Gateway 单实例代码闭环。阶段 5 的 Client 控制流现已接入：管理员在 Management 创建员工账号并设置密码；Client 通过 TLS 连接 HUB，以员工账号密码登录，首次成功时由 HUB 创建节点、设备和公钥凭证，之后用 WireGuard X25519 私钥完成设备证明。HUB 校验当前节点、设备、员工和设备凭证状态，提供配置快照并接收运行状态与应用回执。在线节点、设备或所属员工被禁用后，HUB 通知 Client 停止本机隧道；之后的重连会 fail-closed。Client 配置编译读取活动隧道关系、Gateway Endpoint、AllowedIPs 和网络站点/NAT。Client 隧道应用当前只支持 Windows CLI。

Gateway 与 Client 都在认证后的 Welcome 或状态应答中接收当前配置，并按 canonical SHA-256 摘要对账。Gateway Agent 应用摘要不同的配置后记录任务回执；Client 控制流接收回执并报告运行状态。Gateway 状态反映本地 Reconciler 配置阶段，不代表最近 WireGuard 握手或端到端可达性；Peer 数目前标记未知。当前 Client 配置编译还缺 Management 隧道 Peer 关联界面，无法仅通过控制台建立 Client 与 Gateway 的逻辑隧道成员关系，因此该项是端到端自动配置的剩余阻塞。管理端在线状态查询、Client 撤销回执持久化、跨 HUB 会话协调和多实例 HA 也未完成。

X25519 挑战应答采用 HUB 临时私钥、Gateway 已注册静态私钥与一次性随机挑战。证明密钥经 HKDF-SHA256 派生，MAC 覆盖节点 ID、HUB 实例、挑战、公钥和通道绑定。TLS 模式使用 TLS exporter 将证明绑定到当前连接；明文模式使用域分隔的挑战上下文，但不提供传输机密性、完整性或 HUB 服务端认证。明文仅适用于隔离的开发网络，生产部署应启用 TLS。算法仅用于节点密钥持有证明，不提供公钥签名或不可否认性。Gateway 私钥同时用于 WireGuard 和控制认证的跨协议密钥复用，进入生产部署前须完成独立密码学审查。
