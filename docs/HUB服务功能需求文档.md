# VeloTrust HUB 服务功能需求

- 文档状态：需求基线
- 适用组件：HUB、Gateway Agent、Client Agent、Management
- 当前协议基线：gRPC over HTTP/2 + Protocol Buffers，双向控制流
- 业务依据：[VeloTrust 数据模型设计文档](VeloTrust_数据模型设计文档_最终版.md)、[运行节点与网关注册数据库设计](database/design/ztna_node_data_design.md)、[配置发布与节点状态数据库设计](database/design/ztna_config_data_design.md)、[网关节点技术实现方案](VeloTrust-网关节点技术实现方案.md)、[客户端技术实现方案](VeloTrust-客户端技术实现方案.md)

## 1. 文档目的

本文定义 HUB 服务需要提供的业务能力、与 Management 及运行节点的职责边界、运行和故障行为，以及功能验收标准。本文是后续 HUB 业务实现、协议补充和联调验收的需求依据。

当前代码已具备可选 TLS 的 gRPC 监听、Gateway 与 Client X25519 挑战应答、Gateway 一次性凭证消费与公钥绑定、员工账号密码登录及首次 Client 设备登记、IAM 用户组/成员管理、按地址池员工组关联自动分配 Client IP 租约、单实例内存会话租约、节点心跳与运行状态持久化、Gateway/Client 当前配置编译与同步，以及在线 Client 撤销通知和本机隧道清理。Client 员工密码认证强制使用 TLS。仍未形成完整产品闭环的部分包括 Gateway 隧道 Peer 拓扑管理 UI、管理端在线状态查询、显式撤销执行回执、跨实例会话协调和多实例 HA。明文模式不提供传输加密、消息完整性或 HUB 服务端身份认证，仅适用于隔离开发网络；Client 密码认证不允许使用明文模式。本文其余验收要求不表示功能已经实现。

## 2. 产品边界

### 2.1 HUB 的职责

HUB 是运行控制平面，负责：

- 接收 Gateway Agent 和 Client Agent 的控制连接并认证节点身份。
- 校验节点生命周期状态和注册凭证，维护节点控制会话及在线状态。
- 读取当前期望配置并向目标节点同步，跟踪节点接收、应用和验证结果。
- 接收心跳、配置回执、Peer 与运行健康状态，提供运行状态记录。
- 向在线节点发送重新认证、配置更新和撤销通知；离线期间保留待处理状态，节点重连后重新校验。

Gateway 与 Client 的业务流量原则上由 WireGuard 隧道直接传输，不经 HUB 中转。HUB 控制通道不承载业务数据面流量。

### 2.2 Management 的职责

Management 是管理身份和授权数据的业务权威，负责：

- 平台管理账号认证和 RBAC；员工账号的创建、禁用与密码维护。
- 节点目录、节点生命周期审批、注册凭证签发与撤销。
- 网络、资源、访问策略及节点当前期望配置。
- 管理操作审计和业务状态变更。

HUB 可独立部署并直接访问共享数据库，但必须通过明确的 Repository 和事务接口读取或更新其负责的运行数据。HUB 不复制 Management 的身份、设备、策略业务规则，不把数据库实体直接作为 Agent 协议对象，也不在业务服务中拼接 SQL。

Gateway 首次注册使用 Management 签发的一次性注册凭证；注册成功后凭证立即作废。后续 Gateway Agent 每次建立 gRPC 控制流时，先用已注册的 WireGuard X25519 节点密钥完成 DH 密钥持有证明；HUB 根据节点目录中的公钥验证证明，通过后才接受心跳、配置回执和运行状态。注册凭证不得作为长期控制通道凭证或用于续期认证。该流程属于 X25519 挑战应答/认证密钥协商，不是数字签名。

## 3. 用户与节点类型

| 主体 | 说明 | 首期范围 |
|---|---|---|
| Management | 配置节点、签发或撤销准入凭证、审批和授权 | 必须接入 |
| Gateway Agent | 承载站点网络接入并落实下发配置 | 必须接入 |
| Client Agent | 终端身份接入并落实隧道、本机路由等配置 | 必须接入 |
| Relay、Connector | 后续可扩展的运行节点 | 当前不纳入首期控制闭环 |

数据库统一节点类型还包含 `relay` 和 `connector`。HUB 的协议和模块边界不得假定节点类型永远只有 Gateway 与 Client；但首期不要求实现 Relay、Connector 的具体业务行为。

## 4. 部署模式与阶段

| 阶段 | 部署形态 | 目标 |
|---|---|---|
| 首期 | 单个 HUB 实例；可独立部署，也可与 Management 合并进程运行 | 完成 Gateway 和 Client 的准入、控制流、配置同步、状态上报与撤销闭环 |
| 后续 HA | 多个 HUB 实例，Management 独立运行，各实例共享数据库及运行协调能力 | 支持跨实例会话归属、消息派发、配置一致性及实例故障恢复 |

合并部署只改变进程和运维边界，不得形成另一份 HUB 业务实现。Management 和 HUB 可以独立启停、监听不同地址并按各自职责处理请求。多实例能力属于总体产品需求，首期的功能验收不以 HA 协调已完成为前提。

## 5. 功能需求

优先级说明：P0 为首期控制闭环必需；P1 为总体需求中的后续 HA 能力。

| 编号 | 优先级 | 功能 | 需求与验收结果 |
|---|---|---|---|
| HUB-FR-001 | P0 | 安全传输与服务健康 | 生产控制通道应使用 TLS；隔离开发环境可显式关闭 TLS，但必须保留节点认证，且不得将明文模式用于不可信网络。未完成节点认证的连接不得获得业务控制能力。健康检查应区分服务进程可用与依赖项状态，不能把 TLS 握手成功当作节点已授权。 |
| HUB-FR-002 | P0 | Gateway 首次准入 | Gateway 仅在首次注册时使用 Management 签发的一次性注册凭证。HUB 通过凭证摘要解析其绑定的预建节点，并校验凭证状态、有效期、剩余次数、目标节点类型及节点状态；以事务原子消费凭证并绑定 Gateway 的 WireGuard X25519 公钥。注册成功即将凭证置为已使用；过期、撤销、重复使用、类型错误或公钥冲突均拒绝准入。 |
| HUB-FR-003 | P0 | Gateway 审批 | 对要求审批的 Gateway，注册完成只建立待审批状态；审批完成并且节点状态可接入后，HUB 才允许获得运行配置。待审批、停用、隔离或撤销的节点不得建立有效运行会话或收到授权配置。 |
| HUB-FR-004 | P0 | Client 身份认证与设备登记 | 管理员在 Management 员工用户页面创建带密码的员工账号；员工通过 Client Agent 向 HUB 提交账号密码，Client 不调用 Management 登录或注册 API。密码只能经 TLS 传输。HUB 校验员工账号状态和密码；首次登录时，在单个事务内创建节点、设备和 WireGuard X25519 公钥凭证。每次连接还须完成与该公钥匹配的 X25519 挑战应答；已绑定的员工、设备或公钥不匹配时拒绝连接。客户端自报的 node ID 不构成可信身份。 |
| HUB-FR-005 | P0 | 节点授权 | 每次 Gateway 或 Client 新建或恢复控制会话时，HUB 校验节点类型、生命周期状态、关联设备/用户状态及 WireGuard 公钥绑定一致。Gateway 必须先用已注册 X25519 私钥完成新鲜挑战应答；Client 还须通过员工密码认证。Gateway 一次性注册凭证不得用于后续认证。状态未知或校验失败时拒绝控制连接和配置下发，并记录可追踪的错误代码。 |
| HUB-FR-006 | P0 | 双向控制会话 | Gateway 和 Client 通过 gRPC 双向流发送初始身份信息、心跳、配置应用回执和运行状态；HUB 返回认证挑战、会话建立信息、心跳确认、配置快照及重新认证或撤销类控制消息。两类节点都必须先完成 X25519 身份认证，之后才可处理控制业务消息；心跳、回执和状态消息绑定到该已认证流。服务端必须处理异常断开、取消、超时和优雅关闭。 |
| HUB-FR-007 | P0 | 心跳与在线状态 | HUB 校验心跳属于当前已认证会话并防止旧会话或乱序消息覆盖当前状态。成功心跳更新最后活跃时间；超过部署配置的失联判定阈值后，节点状态应反映为离线或不健康。心跳周期与失联阈值需可配置，不在本文固定数值。 |
| HUB-FR-008 | P0 | 当前配置同步 | 节点连接、重连或发现节点配置摘要不一致时，HUB 从当前权威配置读取目标节点配置并发送快照。配置按 `config_hash` 比较和幂等应用，不把 hash 当成配置版本号，也不依赖配置历史版本。节点身份、目标节点和配置内容必须匹配。 |
| HUB-FR-009 | P0 | 配置应用回执 | HUB 区分任务已发送、节点已接收、节点已应用和配置已验证。发送成功不能视为节点已应用；节点失败回执应保存稳定错误码和脱敏摘要。重复或过期回执不得使较新的配置状态倒退。 |
| HUB-FR-010 | P0 | 配置变更通知 | Management 更新节点当前配置后，HUB 应尽快通知在线目标节点并创建或推进对应分发任务。通知丢失、实例重启或节点离线时，HUB 通过重新读取当前数据库配置和 hash 对账恢复收敛。不能只依赖一次性内存消息。 |
| HUB-FR-011 | P0 | 撤销与隔离 | 节点被禁用、隔离或撤销后，在线会话应收到撤销或重新认证通知；HUB 拒绝后续配置和受保护控制操作，并确认节点侧撤销的实际结果。节点离线时记录待处理撤销；节点重连时必须先校验当前状态，禁止恢复已失效授权。不能仅以消息入队或连接关闭作为数据面撤销完成。 |
| HUB-FR-012 | P0 | 离线授权行为 | Gateway 与 HUB 断开时可以继续使用已应用配置；Client 的普通短暂断连也会保留已建立隧道。在线 Client 收到撤销通知会立即清理隧道；离线 Client 无法即时获知管理侧撤销，重连时必须重新认证并在拒绝前清理本地隧道。当前策略没有固定离线 TTL；节点离线期间不得扩大授权范围。 |
| HUB-FR-013 | P0 | 运行状态上报 | HUB 接收并保存或转发节点类型、Agent 版本、实际配置 hash、WireGuard 状态、连接 Peer 数及其是否可测、健康状态、错误码和上报时间。仅接受经过认证的节点状态；拒绝乱序状态使当前实际状态回退。无法可靠观测的指标必须标记为未知，不能以占位 0 表示实测为零。状态上报不代替独立的隧道握手或资源连通性验证。 |
| HUB-FR-014 | P0 | 审计与诊断 | 记录凭证使用结果、认证失败、会话建立和关闭、配置任务状态变化、撤销执行结果及服务依赖故障。日志和诊断信息不得包含注册凭证明文、长期私钥、认证秘密或完整会话令牌；对节点和任务使用稳定 ID 与错误码关联。 |
| HUB-FR-015 | P0 | 配置与生命周期 | HUB 支持稳定且唯一的 `instance_id`、TLS 证书配置、监听地址、优雅关闭和标准健康检查。与 Management 合并部署时仍可独立启停 HUB 服务模块；分离部署时使用同一套服务实现和共享业务数据边界。 |
| HUB-FR-016 | P1 | 多实例会话归属 | 每个运行会话应能标识其 HUB 实例归属和有效租约。实例需要续租、释放和清理过期会话；进程内存不能作为 HA 模式下唯一权威状态。实例失效后，节点可重连到其他实例并重新验证。 |
| HUB-FR-017 | P1 | 跨实例控制消息派发 | 发往节点的配置、撤销和重新认证消息必须路由到当前拥有节点会话的实例，或进入可恢复的共享队列。不能在没有活跃流或可靠队列接收的情况下声称派发成功。实例切换时消息应可重试且幂等。 |
| HUB-FR-018 | P1 | 多实例配置收敛与恢复 | 多实例应共享当前权威配置和可恢复的节点状态；数据库事件通知可用于加速同步，周期性对账用于修复通知丢失。实例故障后应重新加载当前节点状态和配置，并安全处理未完成任务、旧回执和过期租约。 |
| HUB-FR-019 | P1 | 多实例运维可观测性 | 运维指标能够区分实例健康、在线节点数、会话租约、配置同步延迟、回执状态、撤销待处理数、认证失败数及跨实例派发失败。实例身份和节点状态可用于定位故障，不依赖单实例本地缓存作为唯一数据源。 |

## 6. 主要业务流程

### 6.1 Gateway 注册与接入

1. Management 预建 Gateway 节点并签发一次性注册凭证。
2. Gateway Agent 与 HUB 建立 gRPC 控制流（TLS 可选），提交首次注册凭证、节点类别和 WireGuard X25519 公钥，不自报节点编码；HUB 通过凭证摘要解析预建节点，并以临时 DH 挑战确认 Agent 持有对应私钥。明文模式只允许用于受信任的隔离网络。
3. HUB 校验凭证、节点目录、审批要求、公钥唯一性和节点状态，并原子消费凭证、绑定 WireGuard 公钥及更新注册状态；凭证随即失效，不可再次认证或续期。
4. 若节点需要审批，则保持不可运行状态，等待 Management 完成审批。
5. Gateway 每次打开 gRPC 控制流时先完成 X25519 挑战应答；HUB 以注册时保存的 WireGuard 公钥验证密钥持有证明，通过后才建立授权会话并读取、下发 Gateway 当前期望配置。
6. Gateway 应用配置后回传成功或失败结果及实际运行状态。

### 6.2 Client 接入

1. 管理员已在 Management「员工用户管理」创建带密码的员工账号；设备本地生成唯一 WireGuard X25519 密钥对。
2. 员工在 Client Agent 输入账号密码，Client 直接通过 TLS 连接 HUB，不调用 Management API。HUB 校验凭证，并在首次登录事务中创建节点、设备和设备公钥凭证。
3. 每次连接均使用员工账号密码完成登录，并以同一设备私钥完成新鲜 X25519 挑战应答；HUB 检查员工、节点和设备均有效后建立控制会话。
4. HUB 按设备所有者直接所属的活动员工组匹配地址池的 `client_group_id`，在注册/登录事务中分配持久 IPAM 租约；后续同步会幂等复用租约。该分配流程不创建 Client Peer，也不选择 Gateway。Client 配置中的隧道地址必须与 IPAM 租约一致，Peer 和 Gateway 集合由访问策略配置决定。

### 6.3 配置更新与撤销

1. Management 提交新的当前配置或改变节点状态。
2. HUB 获取当前配置 hash 或节点最新状态，生成可追踪的同步/撤销任务。
3. 在线节点通过控制流接收操作并返回接收、应用结果；HUB 持久化各阶段状态。
4. 离线节点的任务保持可恢复；重连时先重新认证并比较当前数据库状态，取消过期配置任务并优先执行撤销。
5. 只有收到可信回执并完成要求的状态验证后，才能将节点标记为配置已应用或撤销已生效。

## 7. 安全与可靠性约束

- TLS（启用时）保护传输，不代替节点身份认证、凭证撤销检查或设备状态授权。明文模式不提供加密、消息完整性或 HUB 服务端认证，只可用于隔离开发网络。
- Gateway 的 gRPC 控制流认证使用已注册的 WireGuard X25519 密钥执行 DH 挑战应答。HUB 根据公钥查找已注册节点，发出一次性随机挑战和临时 X25519 公钥，并在挑战中返回解析出的节点编码；Gateway 与 HUB 分别计算相同 DH 共享秘密，并基于带协议域分离的 KDF/HMAC 校验密钥持有。挑战必须绑定节点 ID、服务端实例、gRPC 会话及通道上下文；TLS 模式使用 TLS exporter，显式明文模式使用独立域分离的挑战上下文。挑战限时、单次使用；拒绝全零 DH 输出并以常数时间比较证明值。新 gRPC 流必须重新认证。
- X25519 认证是密钥持有证明，不是公钥签名或不可否认性证明。TLS 启用时，成功认证后的流内消息由 TLS 加密并提供完整性保护；明文模式没有这些传输保护。无需将 X25519 描述为逐条 RPC 签名。
- 注册凭证仅用于首次准入，必须限时、限次、可撤销；数据库只保存安全摘要，不记录明文凭证。
- 注册成功后立即原子消费一次性注册凭证；后续 Gateway 控制交互一律使用 X25519 密钥持有认证，不允许回退到注册凭证。
- 节点私钥和长期认证凭证不得通过配置快照、普通日志、审计详情或错误信息泄漏。
- 身份或节点状态未知、校验失败、配置损坏时，HUB 不得向节点发放新的授权配置；节点端不得因控制通道错误而扩大权限。
- 配置应用、任务重试、撤销、重复心跳和 Agent 重启恢复应可幂等；旧任务或旧回执不能覆盖较新的期望状态。
- HUB 的数据访问通过 Repository/事务边界，注册凭证消费、公钥绑定及关键生命周期状态迁移须具备并发安全性。
- 业务控制消息与业务流量分离；HUB 故障不应被描述为业务流量必然经过或必须经过 HUB 转发。

## 8. 验收场景

首期至少通过以下验收：

1. 有效 Gateway 注册凭证只成功用于首次注册一次；注册完成后凭证立即失效，重放、过期、撤销凭证和不匹配节点类型均被拒绝。
2. Gateway WireGuard 公钥与其他节点冲突时，准入失败且数据库中不留下半完成的凭证消费或密钥绑定状态。
3. 注册后的 Gateway 使用对应 X25519 私钥完成新鲜挑战应答时认证成功；错误密钥、全零 DH 输出、过期挑战、跨会话重放以及再次提交注册凭证均认证失败。
4. 需要审批的 Gateway 在审批前不能收到运行配置；审批后可通过 X25519 认证、同步配置并上报状态。
5. Client 使用员工账号密码经 TLS 首次登录并登记设备；伪造 node ID、错误私钥、禁用设备或停用员工不能建立有效会话。后续重连仍向 HUB 提交员工凭证，不依赖 Management API。
6. Agent 首次连接和重连都能取得当前期望配置；重复应用同一 hash 不产生重复副作用。
7. 配置应用成功、失败、迟到及重复回执分别得到正确任务状态；旧回执不能覆盖新配置结果。
8. Management 修改当前配置后，在线节点收到更新；离线节点重连后按当前配置对账，不应用过期任务。
9. 在线节点被撤销后收到撤销通知并回传真实执行结果；离线节点在断开期间按本地现有配置继续，重连后在取得配置前被拒绝并执行待处理撤销。
10. HUB 或数据库不可用时，不能创建未经验证的新会话或下发新配置；已经应用的离线授权按第 5 节规定继续到收到撤销。
11. 运行日志、审计及错误路径中不出现注册凭证明文、私钥或长期认证秘密。
12. 合并部署与独立部署使用相同业务实现；HUB 生命周期可独立控制，健康检查能反映服务状态。

多实例阶段另行验收：会话租约获取/续期/过期、跨实例配置和撤销派发、实例故障后重连、通知丢失后的配置对账、重复任务幂等以及实例恢复时不恢复已撤销节点授权。

## 9. 当前实现缺口与后续设计输入

当前 `shared/proto/v1/hub.proto` 定义 Gateway/Client Hello、心跳、运行状态、Welcome、配置快照、配置应用回执、重新认证及 X25519 挑战/证明消息。HUB 忽略客户端自报的 node ID；Gateway 按已注册 WireGuard 公钥查询，Client 通过 TLS 提交员工账号密码和本机公钥，首次登录时由 HUB 原子创建节点、设备及公钥凭证，后续连接按已绑定公钥查询。Gateway 和 Client 都使用 gRPC 控制连接；TLS 模式验证服务端证书并使用 TLS exporter 绑定挑战，明文模式只用于隔离开发场景。Gateway 身份按节点状态及公钥验证；Client 还须校验员工密码、活动设备、所属用户及设备公钥凭证。Client 不调用 Management API。HUB 从当前节点、活动 Peer、站点网络、NAT 台账、企业资源和访问策略编译配置快照，计算 canonical SHA-256 摘要；不保存额外 JSON 配置副本。Client 地址由设备所有者的活动员工组匹配 `t_ztna_address_pool.client_group_id` 后自动分配。策略关联安全用户组与企业资源；HUB 解析设备 Overlay 租约作为 ACL 来源，并由资源地址、服务端口、站点 NAT 映射及 Gateway 关系生成 Client Peer/路由和 Gateway ACL。策略、资源、用户组及地址租约变化会通知相关节点重新对账；没有匹配 allow 时 Gateway 默认拒绝。配置任务记录 Gateway 与 Client 的发送和应用回执；节点状态报告记录运行快照。在线 Client 收到撤销通知后清理本机隧道；离线 Client 在重连时重新认证失败并清理本机配置。撤销的 Client 本机清理结果未以独立持久化确认记录。HUB 的会话租约仍仅支持单实例，管理端在线状态查询和跨实例会话协调未完成。

现有数据模型已有统一 `t_ztna_node`、Gateway 一次性注册凭证、当前配置、配置任务/事件和节点状态报告；数据库设计明确指出当前没有 HUB 实例归属或分布式租约表。因此：

- 首期实现应复用当前节点和配置权威数据，按最小必要范围持久化运行会话与回执。
- 当前 `t_ztna_node.public_key` 对应 WireGuard X25519 公钥，可同时作为 Gateway 的 DH 密钥持有认证公钥；首期不新增另一类身份密钥字段。挑战应答协议需单独进行安全评审，明确协议域分离、TLS 通道绑定、过期与重放处理、全零 DH 拒绝及密钥复用的安全边界。
- 多实例阶段需要补充共享会话归属、租约和消息派发方案及相应迁移；不能仅凭进程内存、配置任务表或数据库轮询宣称完成 HA。
- 员工账号与平台管理账号使用不同的 `account_type`：员工账号由 Management 创建和重置密码，只能用于 Client Agent 经 TLS 登录 HUB；员工登录不创建 Management 会话，也不授予 IAM 管理角色。Client 首次设备准入由 HUB 在验证员工凭证后事务性完成，不使用 Management 签发的 Client 注册 Token。
- 本文选择普通短断连期间保留已应用配置；在线 Client 收到撤销通知后清理本机隧道。若要求节点长期离线时也能保证撤销时限，需为配置增加可验证的授权有效期。
